Unity 项目迁移鸿蒙（三）：SDK 接入与双向通信

发表于2026-08-18|更新于2026-09-24|游戏开发
|总字数:1.8k|阅读时长:6分钟|浏览量:

将 Unity 项目迁移到 HarmonyOS 后，登录、支付、统计等第三方 SDK 通常需要在 ArkTS 层接入，再通过桥接接口与团结引擎中的 C# 代码通信。本文将梳理 entry 与 tuanjieLib 的职责，介绍本地 HAR 包和中心仓依赖的接入方式，并给出 C# 与 ArkTS 双向调用的基本写法。

接入前先理解模块职责

DevEco Studio 工程与 Android Studio 工程在模块组织上有一些相似之处。在 HarmonyOS 的 Hvigor 构建体系中，每个模块都是独立的编译单元，entry 和 tuanjieLib 分别拥有自己的 oh-package.json5。

  • entry：应用入口模块，承载 Ability 生命周期，适合处理必须依赖应用上下文或生命周期回调的逻辑。
  • tuanjieLib：团结引擎运行模块，适合封装 SDK 能力、桥接接口以及与 C# 交互的代码。

如果把全部 SDK 逻辑都堆在 entry 中，TuanjiePlayerAbility 会很快变得臃肿。更清晰的做法是：在 tuanjieLib 中封装 SDK，在 entry 中仅保留生命周期调用和必要的上下文传递。

在 DevEco Studio 工程中接入 SDK

第三方 SDK 常见的接入方式有两种：引入本地 HAR 包，或者通过 OpenHarmony 三方库中心仓添加依赖。

方式一：引入本地 HAR 包

由于 SDK 需要在 TuanjiePlayerAbility 生命周期中直接调用，所以这一步直接在 entry 模块中引入 SDK。如果引入过程中需要额外封装，可以在 tuanjieLib 中新建 GameSdk 目录承载封装代码，再暴露给 entry 的 TuanjiePlayerAbility 引用。

1. 创建 SDK 代码目录

直接在 entry 中调用 SDK 时，把引入代码写在 entry/src/main/ets 下即可。需要封装时，再在 tuanjieLib/src/main/ets 下创建 GameSdk 目录，并新建 YourSDK.ets。建议把第三方 SDK 的初始化、登录和回调处理统一封装在这个类中，避免业务层直接依赖 SDK 的原始接口。

方式二：使用 OpenHarmony 三方库中心仓

如果 SDK 已发布到 OpenHarmony 三方库中心仓，可以直接在模块的 oh-package.json5 中声明版本依赖，使用方式类似于 Android Gradle 中的远程依赖：

检查 SDK 的间接依赖

DevEco Studio 工程中的 HAR 依赖不一定会自动补齐 SDK 使用的全部间接依赖。如果构建时出现模块找不到、符号缺失等错误，应检查 SDK 文档或 HAR 包的依赖声明，并在当前模块的 oh-package.json5 中显式添加缺失的库。
