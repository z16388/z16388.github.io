Unity Android 混淆踩坑：升级 AGP 后找不到 Java 方法

发表于2026-09-16|更新于2026-09-17|游戏开发
|总字数:889|阅读时长:3分钟|浏览量:

打新版本 APK 时，我遇到了一个问题：应用启动后黑屏，日志提示 Unity 找不到对应的 Java 方法。这个版本的 C# 和 Java 代码都没有修改，构建配置却有一处变化：Android Gradle Plugin（AGP）从 8.2.2 升级到了 8.6.0。

排查后，我把问题定位到了 AGP 8.4 开始引入的库模块缩减行为变化。本文记录这个变化如何影响 Unity 导出工程，以及混淆规则应该放在哪里。

为什么没改代码，方法却找不到了？

这里升级的是 AGP 插件版本，要和 gradle-wrapper.properties 中的 Gradle 版本区分开。两者有关联，但不是同一个版本号。

AGP 8.4 发布说明提到：如果 Android 库子项目开启了代码缩减，提供给依赖它的应用模块的将是缩减后的类。

放到 Unity 导出工程中，可以这样理解：launcher 是应用模块，依赖 unityLibrary 库模块。如果 unityLibrary 开启了 minifyEnabled，它的代码就可能先被处理，再交给 launcher 打包。不能再依赖旧版本中应用模块拿到未缩减库代码的行为。

而我配置的混淆规则中，没有明确类名，而是使用* implements 进行匹配。因为 AGP 规则的修改，就导致我的规则不再生效了。
